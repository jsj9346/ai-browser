# AI 브라우저 아키텍처 (초안)

개발자용 AI 전용 브라우저의 첫 버전 설계입니다. Electron과 TypeScript로 만들고, Linux를 먼저 지원한 뒤 macOS로 넓힙니다.

이 저장소의 Chrome 확장을 Electron 앱으로 교체했습니다. 확장 코드는 git 기록에 남아 있습니다.

## 차별점

다른 제품과 구분되는 점은 네 가지이며, 모두 프롬프트가 아니라 코드로 강제합니다.

1. **작업별 로그인 격리:** 작업은 허용된 로그인만 볼 수 있습니다.
2. **외부 전송 통제:** 작업은 허용된 사이트로만 데이터를 보낼 수 있습니다.
3. **연결 방식과 무관한 동일 규칙:** 내장 에이전트와 외부 에이전트(MCP/CLI)가 같은 검사를 거칩니다.
4. **Linux 우선 지원**

## 스파이크로 확인한 것

코드는 별도 저장소 `~/ai-browser-spike`에 있습니다.

| 항목 | 결과 |
|---|---|
| 세션 격리와 전송 차단 자동 테스트 | Linux, 샌드박스 켬: 통과 41, 실패 4, 판정 불가 4, 참고 3 |
| Google, GitHub 실제 로그인 | macOS, 집 인터넷, 기본 User-Agent: 성공 (사용자 보고) |
| 로그인 쿠키를 작업 세션으로 복사 | GitHub 성공 (16/16), Google 실패 (15/15 복사 후에도 재로그인 요구, 원인 미상) |

실패 4건은 대응 방법까지 설계에 반영했습니다.

| 실패 | 대응 |
|---|---|
| raw CDP `Target.getTargets`로 다른 세션의 페이지가 보임 | CDP 허용 목록 |
| raw CDP로 다른 세션 페이지에 연결해 HttpOnly 쿠키를 읽음 | CDP 허용 목록 |
| CDP `loadNetworkResource`가 요청 차단을 우회함 | CDP 허용 목록 + 허용 목록 프록시 (스파이크에서 프록시가 차단함) |
| WebRTC STUN이 요청 차단을 우회함 | WebRTC UDP 정책 (스파이크에서 정책이 차단함) |

아직 모르는 것:

- **Linux에서의 실제 로그인:** 이 서버에는 화면이 없어 아직 해 보지 못했습니다.
- **로그인 유지:** 시간이 지나도 유지되는지, 나중에 차단되지 않는지 모릅니다.
- **전송 차단의 남은 경로:** preconnect, speculation prefetch, dns-prefetch, 차단된 요청의 DNS 조회는 판정 불가이고, WebTransport/QUIC은 테스트하지 않았습니다.

## 구조

```text
Electron 메인 프로세스
├─ 화면(shell): 작업 목록, 승인 창, 로그인 화면
├─ TaskManager: 작업 생성과 종료
│   └─ Task (작업마다 하나)
│       ├─ Session: 전용 partition
│       ├─ EgressGuard: 요청 차단 + 허용 목록 프록시 + WebRTC 정책
│       ├─ 페이지: 샌드박스된 WebContentsView (preload 없음)
│       ├─ GatedCdp: 허용된 CDP 명령만 통과
│       └─ ToolExecutor: policy 검사와 사용자 승인
├─ 내장 에이전트: agent 루프 → ToolExecutor
└─ 외부 연결 서버: 권한 0600 Unix 소켓 → ToolExecutor

외부 에이전트 → MCP/CLI 브리지 → Unix 소켓
```

내장 에이전트와 외부 에이전트는 모두 `ToolExecutor`로만 브라우저를 조작합니다. 차별점 3은 이 구조로 보장합니다.

## 보안 규칙

기존 `CLAUDE.md`의 불변식(안전 검사는 코드에, 페이지 내용은 신뢰하지 않음 등)을 그대로 유지하고, 다음을 추가합니다.

- **raw CDP는 어디에도 노출하지 않습니다.** 모델과 외부 에이전트는 물론 내부 코드도 `GatedCdp`로만 보냅니다. 허용 목록은 `browser.ts`가 실제로 쓰는 명령으로 시작하며, `Target.*`, `Network.loadNetworkResource`, `Storage.*`는 넣지 않습니다.
- **`Runtime.evaluate`와 `Runtime.callFunctionOn`은 내부 고정 코드만 실행합니다.** 임의 코드 실행을 도구로 제공하면 전송 통제를 페이지 안에서 시도할 수 있으므로 첫 버전에는 넣지 않습니다.
- **전송 통제는 세 겹을 모두 켭니다.** 스파이크에서 요청 차단만으로는 뚫리는 경로가 있었습니다. 설정 중 하나라도 실패하면 작업을 시작하지 않습니다.
- **승인은 앱 화면에서만 받습니다.** 외부 에이전트는 승인을 요청할 수만 있고, 응답할 수 없습니다.
- **로그인 중에는 에이전트를 멈춥니다.** 사용자가 작업 창에서 로그인하는 동안 도구 호출을 거부합니다. 비밀번호 입력란 차단은 `policy.ts`의 규칙을 유지합니다.
- **쿠키 값은 기록하지 않습니다.** 로그에는 개수와 이름만 남깁니다.
- **`--no-sandbox`로 배포하지 않습니다.**
- **API 키는 메인 프로세스에만 둡니다.** `safeStorage`로 암호화하되, Linux에 키링이 없으면 약한 저장 방식(`basic_text`)이 선택될 수 있습니다. 이 경우 조용히 저장하지 않고 사용자에게 알립니다.

## 로그인 방식

Google에서 쿠키 복사가 실패했으므로 복사를 기본으로 삼지 않습니다.

| 방식 | 동작 | 용도 |
|---|---|---|
| 작업 안에서 직접 로그인 (기본) | 빈 세션에서 사용자가 로그인 | 모든 사이트 |
| 저장 프로필 (선택) | `persist:` partition에 로그인을 남겨 프로젝트별로 재사용 | 매번 로그인하기 번거로운 경우 |
| 기존 로그인 복사 (선택) | 고른 사이트의 쿠키만 작업에 복사 | GitHub처럼 복사가 되는 사이트 |

- 기본 작업 세션은 메모리에만 있어서 작업이 끝나면 로그인이 사라집니다.
- 복사 후 로그인 상태가 아니면 성공으로 표시하지 않고 직접 로그인을 안내합니다.
- 직접 로그인은 스파이크의 첫 로그인과 같은 조건(빈 세션)입니다. 다만 Google에서 반복 로그인이 추가 인증을 부르는지는 아직 확인하지 않았습니다.

## 기존 코드 재사용

| 파일 | 처리 |
|---|---|
| `src/policy.ts` | 그대로 사용 |
| `src/ax.ts` | 그대로 사용 |
| `src/tools.ts` | 도구 정의와 `ToolExecutor` 유지, 승인 사이트를 EgressGuard 허용 목록과 연결 |
| `src/agent.ts` | 메인 프로세스로 이동 |
| `src/browser.ts` | `Browser` 인터페이스 유지, 구현을 `webContents.debugger` + `GatedCdp`로 교체 |
| `src/sidepanel.ts`, `src/background.ts` | 새 화면으로 교체 |
| `test/` | 유지하고 전송 통제와 CDP 허용 목록 테스트 추가 |
| `e2e/run.mjs` | 가짜 API와 픽스처 사이트 방식은 유지, 디버깅 포트로 앱을 구동. Playwright의 Electron 실행기는 `--no-sandbox`를 붙이고 이 앱에서 멈춰서 쓰지 않음 |

`tools.ts`의 사이트 승인은 현재 이동이 일어난 뒤에 확인하기도 합니다(`afterAction`). 새 구조에서는 EgressGuard가 요청 전에 막으므로, 허용되지 않은 사이트로의 이동은 요청이 나가기 전에 멈추고 승인을 묻게 됩니다.

## 구현 단계

1. **앱 뼈대 (완료):** Electron 앱, 작업 하나, `GatedCdp`, 기존 도구 연결. 가짜 API E2E 통과. 실제 Claude API로는 아직 실행하지 않았습니다.
2. **격리와 전송 통제:** 작업별 세션, EgressGuard. 스파이크의 자동 테스트를 저장소로 옮기고 판정 불가 항목을 해소.
3. **로그인:** 직접 로그인 흐름, 로그인 중 에이전트 정지, 저장 프로필, 선택적 복사.
4. **화면:** 작업 목록, 승인 창, 차단 내역 표시.
5. **외부 연결:** Unix 소켓과 MCP/CLI 브리지. 내장 에이전트와 같은 테스트를 외부 경로로도 실행.
6. **Linux 배포:** Ubuntu 24.04의 `apparmor_restrict_unprivileged_userns` 제한을 풀 패키지(.deb 설치 시 SUID `chrome-sandbox` 또는 AppArmor 프로필) 구성. 실제 Linux 데스크톱에서 로그인 재검증.
7. **macOS 지원:** 코드 서명과 공증.

Linux 로그인 재검증은 6단계보다 일찍 할 수 있으면 좋습니다. 막힌다면 설계에 영향을 주기 때문입니다.

## 결정이 필요한 것

- **Linux 데스크톱 테스트 환경:** Mac의 Linux 가상머신이나 별도 Linux PC가 필요합니다. 서버에 원격 화면을 붙이면 요청이 데이터센터 IP로 나가므로 결과가 달라질 수 있습니다.
