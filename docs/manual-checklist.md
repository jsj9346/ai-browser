# 3단계 수동 점검표

로그인과 저장 프로필을 사람이 실제 환경에서 확인하는 목록입니다. [3단계 완료 조건](architecture.md#완료-조건)의 "실제 사이트" 항목을 절차와 합격 기준으로 풀었습니다.

- **환경:** Mac과 Mac의 Linux 가상머신. 집 인터넷에서 합니다. 서버는 화면이 없고 데이터센터 IP라 쓰지 않습니다.
- **계정:** 잃어도 괜찮은 계정이 좋습니다. 저장 프로필의 localStorage와 캐시는 디스크에 평문으로 남습니다.
- **코드:** `electron-app` 브랜치.
- **범위 밖:** 패스키는 보장하지 않으므로 확인하지 않습니다. 호스트 차단, 서비스 워커, 사설 IP처럼 측정으로 확인한 항목은 `npm run e2e`와 `npm run e2e:security`가 다룹니다.
- **실패했을 때:** 실패 표시와 함께 화면 문구, 사이트, 환경을 남깁니다.

## 준비

두 환경에서 각각 먼저 합니다. 여기서 막히면 뒤 항목의 결과를 믿을 수 없습니다.

### 설치와 실행

- **환경:** Mac, Linux VM

1. `electron-app` 브랜치를 받아 `npm install`을 실행합니다.
2. `npm start`로 앱을 켭니다.

```bash
npm install
npm start
```

**합격:** 설치 출력에 `Electron cookie encryption is on`이 보이고 창이 뜹니다. `--no-sandbox`는 쓰지 않습니다.

Linux에서 샌드박스 오류로 멈추면 README의 `chrome-sandbox` 권한 명령을 실행합니다. Mac은 fuse를 켠 뒤 재서명하는 경로를 처음 시험하므로, 앱이 뜨지 않으면 그 자체가 중요한 결과입니다.

- [ ] Mac
- [ ] Linux VM
### 패널 한글 표시

- **환경:** Mac, Linux VM

1. 패널의 주소 영역, 프로필, 설정을 펼쳐 봅니다.

**합격:** 글자가 네모로 나오지 않고, 잘리거나 겹치는 문구가 없습니다.

- [ ] Mac
- [ ] Linux VM
### 키링 인식

- **환경:** Mac, Linux VM

1. 패널의 `설정`을 펼칩니다.
2. `프로필`을 펼칩니다.

**합격:** 설정에 `키는 암호화해 이 컴퓨터에 저장합니다.`가, 프로필에 `임시 세션은 작업이 끝나면…`이 보이고 프로필을 만들 수 있습니다.

`이 시스템에서는…`이 보이면 키링이나 fuse 문제입니다. Linux는 데스크톱에 로그인한 세션에서 키링이 잠금 해제되어 있어야 합니다.

- [ ] Mac
- [ ] Linux VM

## 직접 로그인

임시 세션에서 합니다. 주소를 입력한 뒤 `열기`가 아니라 `로그인` 버튼을 누릅니다.

### GitHub 로그인

- **환경:** Mac, Linux VM

1. 주소에 `https://github.com/login`을 넣고 `로그인`을 누릅니다.
2. 페이지에서 비밀번호와 2단계 인증까지 마칩니다.
3. 패널의 `완료`를 누릅니다.
4. 호스트 목록을 보고 `확인`을 누릅니다.

**합격:** 로그인이 끝나고, 목록에 `github.com`만 미리 체크되어 있으며, 확인 후 로그인 상태가 유지됩니다.

- [ ] Mac
- [ ] Linux VM
### Google 로그인

- **환경:** Mac, Linux VM

1. 주소에 `https://accounts.google.com`을 넣고 `로그인`을 누릅니다.
2. 비밀번호와 2단계 인증까지 마칩니다.
3. `완료`를 누르고 호스트를 고릅니다.

**합격:** "안전하지 않은 브라우저" 같은 거부 없이 로그인이 끝납니다.

Linux에서는 아직 한 번도 시도하지 않았습니다. 거부되면 화면 문구를 그대로 메모해 주세요.

- [ ] Mac
- [ ] Linux VM
### 호스트 선택의 효과

- **환경:** Mac, Linux VM

1. 로그인 끝에 추가 호스트를 체크하지 않고 `확인`을 누릅니다.
2. 페이지를 다시 엽니다.

**합격:** 체크하지 않은 호스트가 패널에 `차단됨:`으로 나오고, `허용`을 누르면 그 호스트만 열립니다. 로그인은 유지됩니다.

차단 때문에 사이트가 깨지는 정도를 메모해 주세요. 시작 호스트만으로 쓸 수 있는지 판단하는 자료가 됩니다.

- [ ] Mac
- [ ] Linux VM
### 로그인 취소

- **환경:** Mac, Linux VM

1. 로그인을 시작해 다른 도메인의 페이지까지 간 뒤 `취소`를 누릅니다.

**합격:** 로그인 영역이 닫히고, 방금 지나온 다른 도메인이 다시 차단됩니다.

- [ ] Mac
- [ ] Linux VM

## 팝업 로그인

### 팝업으로 여는 소셜 로그인

- **환경:** Mac, Linux VM

1. "Google로 로그인"이나 "GitHub로 로그인"을 팝업으로 여는 사이트를 고릅니다.
2. 그 사이트 주소로 `로그인`을 누르고 소셜 로그인 버튼을 누릅니다.
3. 팝업에서 인증을 마치고, 패널에서 `완료`와 `확인`을 누릅니다.

**합격:** 팝업 창 제목이 `로그인 창: <실제 주소>`로 나오고, 인증 결과가 원래 페이지로 돌아옵니다. 로그인이 끝나면 팝업이 남아 있지 않습니다.

팝업 대신 같은 창에서 이동하는 사이트는 이 항목의 대상이 아닙니다. 어떤 사이트로 시험했는지 메모해 주세요.

- [ ] Mac
- [ ] Linux VM

## 동결과 시간 제한

이 값들은 출시 빌드에서 줄일 수 없어 실제로 기다려야 합니다. 페이지 입력만 활동으로 세며, 패널 조작은 세지 않습니다.

### 입력 중에는 동결되지 않음

- **환경:** Mac, Linux VM
- **소요:** 약 7분

1. 로그인을 시작합니다.
2. 페이지 안에서 7분 동안 1~2분 간격으로 마우스를 움직이거나 키를 누릅니다.

**합격:** 패널에 `입력이 없거나 화면이 잠겨…` 문구가 나오지 않습니다.

키보드와 마우스 입력을 각각 해 보면 더 좋습니다. 실제 입력은 자동 테스트로 확인하지 못했습니다.

- [ ] Mac
- [ ] Linux VM
### 입력이 없으면 동결

- **환경:** Mac, Linux VM
- **소요:** 약 5분

1. 로그인을 시작하고 페이지를 건드리지 않습니다.

**합격:** 5분 뒤 패널이 `입력이 없거나 화면이 잠겨…`로 바뀌고 `다시 열기` 버튼이 나옵니다.

- [ ] Mac
- [ ] Linux VM
### 동결 중 휴대폰 인증

- **환경:** Mac, Linux VM
- **소요:** 약 5분

1. Google이나 GitHub에서 휴대폰 승인을 요구하는 화면까지 갑니다.
2. 페이지를 건드리지 않고 동결될 때까지 기다립니다.
3. 동결 문구가 나오면 휴대폰에서 승인합니다.

**합격:** `다시 열기`를 누르지 않아도 로그인이 이어집니다.

새 호스트가 필요해서 멈추면 실패로 표시하고, 막힌 호스트를 메모해 주세요. 동결 설계를 바꿀 수 있는 결과입니다.

- [ ] Mac
- [ ] Linux VM
### 동결 후 다시 열기

- **환경:** Mac, Linux VM
- **소요:** 약 5분

1. 동결시킨 뒤, 그때까지 가지 않은 다른 도메인으로 이동합니다.
2. `다시 열기`를 누르고 같은 곳으로 다시 이동합니다.

**합격:** 동결 중에는 막히고, 다시 연 뒤에는 통과합니다. 패널의 `…까지 유효합니다` 시각은 처음과 같습니다.

- [ ] Mac
- [ ] Linux VM
### 화면 잠금 감지

- **환경:** Mac, Linux VM

1. 로그인 중에 화면을 잠급니다.
2. 10초쯤 뒤 잠금을 풉니다.

**합격:** 잠금을 풀었을 때 패널이 동결 문구로 바뀌어 있습니다.

Linux에서 감지되지 않으면 실패로 표시해 주세요. 이 경우 설계상 5분 유휴 동결에 의존합니다.

- [ ] Mac
- [ ] Linux VM
### 절전

- **환경:** Mac, Linux VM

1. 로그인 중에 컴퓨터나 가상머신을 절전시킵니다.
2. 깨웁니다.

**합격:** 깨어났을 때 패널이 동결 문구로 바뀌어 있습니다.

- [ ] Mac
- [ ] Linux VM
### 30분 상한

- **환경:** Mac, Linux VM
- **소요:** 30분

1. 로그인을 시작하고 그대로 둡니다.
2. 패널의 `…까지 유효합니다` 시각이 지날 때까지 기다립니다.

**합격:** 그 시각에 호스트 선택 화면으로 넘어갑니다. 고르기 전에는 새 호스트가 열리지 않습니다.

- [ ] Mac
- [ ] Linux VM
### 다른 디스플레이 서버

- **환경:** Linux VM

1. 현재 세션 종류를 확인합니다.
2. X11과 Wayland 중 쓰지 않은 쪽으로 다시 로그인합니다.
3. 앱을 켜고 `입력 중에는 동결되지 않음`과 `화면 잠금 감지`를 반복합니다.

```bash
echo $XDG_SESSION_TYPE
```

**합격:** 두 세션의 결과가 같습니다.

메모에 어느 세션에서 무엇을 봤는지 적어 주세요. 가상머신에 세션이 하나뿐이면 건너뜀으로 표시합니다.

- [ ] Linux VM

## 저장 프로필

### 프로필 만들기

- **환경:** Mac, Linux VM

1. `프로필`을 펼치고 이름을 넣어 `만들기`를 누릅니다.
2. 안내를 읽고 확인합니다.

**합격:** localStorage와 캐시가 평문으로 남는다는 안내가 먼저 나오고, 확인 후 그 프로필로 바뀝니다.

- [ ] Mac
- [ ] Linux VM
### 재시작 후 로그인 유지

- **환경:** Mac, Linux VM

1. 프로필에서 GitHub나 Google에 로그인하고 호스트를 고릅니다.
2. 앱을 완전히 끄고 다시 켭니다.
3. 그 프로필을 고르고 같은 사이트를 엽니다.

**합격:** 다시 로그인하지 않아도 로그인 상태이고, 고른 호스트가 프로필 목록에 있습니다.

- [ ] Mac
- [ ] Linux VM
### 임시 세션은 남지 않음

- **환경:** Mac, Linux VM

1. 임시 세션에서 로그인합니다.
2. 앱을 끄고 다시 켠 뒤 같은 사이트를 엽니다.

**합격:** 로그아웃 상태입니다.

- [ ] Mac
- [ ] Linux VM
### 쿠키 암호화 (Linux)

- **환경:** Linux VM

1. 로그인한 프로필이 있는 상태에서 앱을 끕니다.
2. 아래 명령을 실행합니다. `sqlite3`가 없으면 먼저 설치합니다.

```bash
find ~/.config/neo-browser/Partitions -name Cookies -exec sqlite3 {} "select cast(substr(encrypted_value,1,3) as text), count(*), sum(length(value)>0) from cookies group by 1" ;
```

**합격:** 접두사가 모두 `v11`이고 마지막 숫자가 0입니다. `v11`이 키링 키로 암호화했다는 뜻입니다.

`v10`이 나오면 실패입니다. 공개된 고정 키로 풀리는 값이라 보호되지 않습니다.

- [ ] Linux VM
### 쿠키 암호화 (Mac)

- **환경:** Mac

1. 로그인한 프로필이 있는 상태에서 앱을 끕니다.
2. 아래 명령을 실행합니다.
3. 키체인 접근 앱에서 `Safe Storage`를 검색합니다.

```bash
find ~/Library/Application\ Support/neo-browser/Partitions -name Cookies -exec sqlite3 {} "select cast(substr(encrypted_value,1,3) as text), count(*), sum(length(value)>0) from cookies group by 1" ;
```

**합격:** 접두사가 모두 `v10`이고 마지막 숫자가 0이며, 키체인에 앱의 `Safe Storage` 항목이 있습니다.

Mac은 Linux와 달리 `v10`이 정상입니다. 이 판정은 Chromium의 동작을 근거로 한 것이고 아직 측정하지 않았습니다.

- [ ] Mac
### 프로필 삭제

- **환경:** Mac, Linux VM

1. 프로필을 고르고 `이 프로필 삭제`를 누릅니다.
2. 앱을 끄고 다시 켠 뒤 다시 끕니다.
3. `Partitions` 폴더를 확인합니다.

**합격:** 프로필이 목록에서 사라지고, 다음 시작 후 그 `profile-…` 폴더가 지워져 있습니다.

- [ ] Mac
- [ ] Linux VM

## 실제 Claude API

이 항목만 API 요금이 듭니다. 지금까지 가짜 API로만 시험했고, 실제 모델이 `request_login`을 부르는지는 모릅니다. 임시 세션에서 합니다.

### 기본 작업

- **환경:** Mac

1. `설정`에 API 키를 저장합니다.
2. `https://example.com`을 열고 `이 페이지의 핵심 내용을 요약해 줘`를 실행합니다.

**합격:** 요약이 패널에 나옵니다.

- [ ] Mac
### 에이전트의 로그인 요청

- **환경:** Mac

1. 로그아웃 상태에서 `https://github.com/settings/profile`을 엽니다.
2. `내 GitHub 프로필 이름을 알려 줘`를 실행합니다.
3. 승인 카드를 승인하고 직접 로그인합니다.
4. `완료`와 `확인`을 누릅니다.

**합격:** `github.com에 로그인할까요?` 카드가 나오고, 모델이 비밀번호를 입력하려 하지 않으며, 로그인 후 작업을 이어 가 이름을 답합니다.

모델이 카드 없이 포기하거나 다른 길을 찾으면 실패입니다. 패널 기록을 그대로 메모해 주세요.

- [ ] Mac
### 로그인 요청 거부

- **환경:** Mac

1. 같은 작업을 로그아웃 상태에서 다시 실행합니다.
2. 승인 카드를 `거부`합니다.

**합격:** 같은 요청을 반복하지 않고, 로그인이 필요해 끝내지 못했다고 답합니다.

- [ ] Mac
